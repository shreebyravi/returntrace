The problem

A return passes through the customer, the courier, the warehouse and the seller, and each keeps its own record. When those records disagree, someone has to rebuild what happened before anyone can decide fairly.

Disputes are rising

In the Merchant Risk Council's 2025 global survey, 57% of merchants reported an increase in refund and policy abuse, and 47% named refund abuse their top fraud attack. These are global figures, not UAE ones.

The evidence is split

Order system, courier tracking, warehouse inspection, support messages and policy versions: each answers part of the question, in a different place.

Fairness cuts both ways

Refunding too easily costs the seller. Denying a genuine customer, or accusing them, costs trust. A careful, evidenced decision protects both.

Source: Merchant Risk Council, 22 July 2025. What we don't know: how often evidence-conflicting disputes happen in UAE marketplaces, or what they cost to investigate.

What already exists, and the gap

Returns software is a crowded market, so ReturnTrace doesn't try to be another returns portal or fraud score.

Already solvedExamplesWhat they do
Return portals and automationLoop Returns, AfterShip Returns, NarvarSelf-service returns, eligibility rules, exchanges, tracking
Return risk scoringLoop Returns fraud toolsScore risk as returns are submitted and hold critical-risk returns before money goes out
Marketplace-native disputesAmazon, noonTheir own return, refund and seller-dispute processes, on their own data
Our hypothesis: scoring decides which returns look risky; it doesn't investigate the ones that end up disputed. ReturnTrace is an investigator-first workspace for those cases: it pulls the evidence together, chooses what to check next, and drafts a neutral, cited recommendation. We have not confirmed that existing products lack this, and no returns team has tested it.

How it works

Code does everything exact. The agent does what needs reading and judgement. A person decides.

01 CHECK

Exact checks

Code checks the return window and policy version, courier events, receipt, inspection, serial, weight and timeline in UTC.

Automatic, no AI
02 INVESTIGATE

Follow the evidence

The agent retrieves records and, when it finds a contradiction, looks for the scan or photo that could settle it.

Agent, with tools
03 SEPARATE

Facts vs conflicts

Confirmed facts, contradictions and missing evidence are listed apart, each with its source and an exact quote.

Agent, checked by code
04 RECOMMEND

One next step

Refund or replacement review, more evidence, or escalation. Rejection only when the policy clearly isn't met and nothing is open.

Agent proposes
05 DECIDE

A person decides

The specialist accepts, asks for evidence, escalates or rejects the recommendation, with a reason. Everything is logged.

Person decides

Why it can be trusted with this job

It never accuses anyone. Code blocks any answer that calls a customer dishonest, and the agent refuses requests to label an account.
It shows its evidence. Every finding cites a record and an exact quote; code checks each quote against the source.
It doesn't do the maths. Windows, policy versions, time zones, serials, weights and refund amounts are calculated by code.
It can't move money. There is no refund, rejection or send action. Requests are drafts.
It escalates when it should. Two policy versions that disagree, a courier and warehouse that disagree, or a system that doesn't respond all go to a person.
Its steps are real. Every tool call and result on screen was logged by code, not described by the model.

What this prototype is, and isn't

A fictional UAE marketplace with 25 orders, 11 return cases, 67 courier events, 9 inspections, 15 scans and photos, 19 messages and three versioned policies, with a separate answer key. The answers shown are recorded examples: real Claude Sonnet sessions that called this app's own tools, recorded on 12 November 2026. Add your own Anthropic API key in Settings to run it live. It isn't connected to any marketplace, courier or warehouse system, and no returns team has used it. See the evaluation for results and limits.

Known limits
  • One fictional marketplace with 11 return cases. Scans and photos are text descriptions, not images.
  • It investigates one case at a time. It doesn't look for patterns across a customer's or seller's history, by design.
  • Policies are a simplified, made-up set. Real marketplaces have seller-specific policies and category rules.
  • Recorded answers come from one run per case. Answers vary between runs; a pilot would need repeated runs and a person checking a sample.
  • No returns team has used it, and nothing is connected to a real order, courier or warehouse system.
